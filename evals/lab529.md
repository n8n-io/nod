## Baseline hypothesis, recorded before execution

Without the history boundary, the background prompt contains the still-running foreground request. The old prompt can treat that unanswered request as unfinished work and issue another calendar change or reply. Predicted baseline evidence: the pending-request exclusion check fails; the actual model may or may not also repeat the change. A baseline that never reaches both turns is an environment/setup failure. A baseline whose exact background prompt excludes the request disproves the context-leak mechanism under this setup. Passing current behavior without a baseline leak would not establish this mechanism's causal relevance.

No runtime change is authorized by this record. Any new failure must first be classified as agent, setup, source or evaluator, with a hypothesis and unchanged-case retest.

## Setup correction and retained version 1

The interrupted version 1 attempt retained both completed app turns but no scored result. Its background Inspector snapshot includes the active user request, supporting the context-leak hypothesis; this partial evidence is not an end-to-end pass. Its measured model cost was USD 0.1022162; judge cost was unavailable. The original manifest, synthetic database observations and Pi session were retained under `.local/capability-evals/lab529-baseline-v1/`.

Review found a setup fault: `localTime` accepts days backward, so version 1 used past dates where the frozen specification required future dates. Before changing the setup, the recorded hypothesis predicted that positive offsets produced October 6/5 and negative offsets would produce October 8/9 at the frozen October 7 clock. Independent ISO-date assertions verify the correction. Version 2 changes only the offset signs; all checks, models, repeats and overlap barriers remain unchanged. The resumed version 1 result is retained separately and does not satisfy the version 2 acceptance gate.
