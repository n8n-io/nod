## Follow-up feedback

- **Match Otto:** proposals reuse the existing Chat, composer, Sidebar, settings, Memory, secure forms, onboarding and browser components, fonts and assets.
- **Message actions:** the floating toolbar remains an option; the reaction trigger, picker and menus follow the app's controls.
- **Uploads:** both alternatives keep small attachment references inside the composer, with byte sizes, progress and removal. Upload delivery remains simulated.
- **Navigation:** proposals preserve continuous chat, center the rail vertically and place search at the top. The command palette is a review option.
- **Settings:** both a dedicated page and a larger modal preserve appearance previews, date/time controls, model settings and Memory. Browse apps and Connected status are shown without redundant readiness copy; easy connect and manual setup are mutually selected.
- **Notifications:** existing preferences and quiet-hours controls remain. No new cross-channel notification-delivery guarantee is claimed.
- **Connecting apps:** proposals use simple contextual cards, provider logos and one primary action.
- **Sign-in:** proposals retain Otto branding, provider method selection, password reveal and beside-chat/standalone layouts. Two-step email has no bottom stepper or oversized new focus border.
- **Empty states:** proposals center clear explanations on pages that can be empty, preserving continuous chat and the existing Memory interface.
- **Browser:** two input bugs are fixed in code. In-chat and focused presentation options remain review proposals; broad website reliability is not established by these checks.
- **Onboarding and feedback:** proposals retain a conversational flow and an anchored feedback hint styled with the app's controls.
- **Onboarding Send position:** restored right alignment after removing the microphone. Synthetic web and desktop renderer checks cover desktop and narrow widths.
- **Secure action buttons:** improved Sign in securely and Confirm payment treatments are being reviewed separately in the local gallery; their new presentation is not installed in this branch.

## Additional bugs found while reviewing

- **ChatGPT connection:** the inspection runtime had a malformed Vault encryption key. With that key, OAuth could complete and then fail when saving the account, returning the generic sign-in error. The runtime key was repaired only after verifying there was no encrypted data. The product now checks credential storage before OAuth, API-key or endpoint connections begin and reports unavailable storage without exposing the underlying error. [Synthetic HTTP/database evidence](model-storage-regression.json) verifies no provider call or saved connection on failure and successful encrypted persistence after correction.
- **Credential status consistency:** form and polling responses now share one status mapper and both scope the operation lookup to its owner. The regression preserves the previous disagreement for a foreign-owned operation and verifies it is expired in both responses after the fix.
- **Review evidence:** current browser source was recaptured, raw PDF images are included with their hashes, and completed-action evidence distinguishes equal fixture state from the changed status-only API route.

## Acceptance limits

The local gallery is a design review, not a product deployment. Desktop screenshots use a renderer bridge fixture. Required Linux integration checks are reported separately from native macOS checks and any live sign-in attempt in the PR description. Native notification permission acceptance, installed-app onboarding and authenticated Instinct comparison are not claimed. Human UI acceptance remains required before merge.
