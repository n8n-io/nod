# Owner experience

Vault has Activity and Saved views. Saved contains logins, local cards and browser sessions. Lists show account metadata, origins, card brand and last four digits. They do not include secret values.

The owner can add, import, edit, reveal and remove their values. Reveals and card permission changes create activity. A hosted legacy card can be read or removed but cannot be edited or added.

An exact local add link can open an empty login or card form. It accepts no credential query fields. If Otto needs a missing card, the owner saves it in Vault and asks Otto to continue.

For Telegram and WhatsApp, private entry stays in Otto on desktop. The chat message directs the owner to Otto. The shared desktop conversation contains the secure form action. After private submission, the task continues in its original channel. No mobile access service is required.

A sign-in that matches the current task runs under a task and item grant. Otherwise Otto asks about the selected account and site. Sign in without asking is an explicit standing site permission. Disabling it or deleting the site's last login removes site grants.

Activity keeps separate uses, questions, held attempts and permission changes. Two sign-ins to the same site are two events. Payment activity reports card submission or uncertainty, with the approved amount. It does not infer a completed payment.

A secure-form failure before use can remain editable. If a use may have reached the website, the form reports uncertainty. The owner must ask Otto to check the result before another attempt. It does not submit again automatically.

Pi retains its normal tools after private entry. A blocked network origin for a saved session can be requested as an extra destination. An owner browser handoff remains available for native sign-in and website flows that require it.
