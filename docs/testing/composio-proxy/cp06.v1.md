## Native base

The actual Electron main process used a separate `OTTO_DESKTOP_USER_DATA` profile containing a completed synthetic setup. It opened the native “Set up your computer” screen with `firstSetup=false`. Selecting “Open Otto” displayed “Choose the Otto Runtime pack to finish setting up this Mac.” The worktree had no runtime asset manifest at its supported locations, so no disposable existing-account database or product window started.

The native settings file remained byte-for-byte unchanged, including completion, theme, notification and startup preferences. Existing main-process contract tests additionally verified that replay requests `/onboarding?replay=1` without restarting the engine or resetting the profile. Those tests do not replace the missing native handoff.

## Web holdout

The actual App, routes and onboarding components ran at separate local development and production origins with persistent synthetic API state. Chrome used its existing browser profile; only the app origins and stores were isolated. The renderer was not replaced with a preview component.

1. Development Settings → Appearance → Replay onboarding opened Welcome and consumed the replay query.
2. The saved model remained selected. At About, browser Back cancelled the flow; a full page reload returned to the retained Gmail connection.
3. Replaying from Settings returned to Welcome. Welcome, Brain, About, Email, Telegram and Open source completed through their real controls. Telegram was skipped without connecting an account.
4. “Start chatting” returned to the original conversation sentinel. The saved Gmail connection, preferences, synthetic credential reference, chat and completed session settings remained equal to the original store.
5. Production Settings had no replay control. Opening `/onboarding?replay=1` directly redirected the completed account to its original conversation.

The valid run took **204.998 seconds**. API observations contained no reconnect, disconnect, reset, key or account mutation. The only writes were account preparation, the explicitly completed synthetic interview, and suggestions requests refused by the evaluator with HTTP 501 to prevent model execution. The real renderer handled that refusal and completed.

Each hypothesis was recorded before correcting the evaluator. Application source, prompt and acceptance checks were unchanged. These measurements were errors, not app failures or passes.

The focused regression runs passed: three native settings/main-process contracts and one production renderer/OAuth contract. All 169 frozen production desktop, shared onboarding and web files remained unchanged during evaluation. The input file was formatted after execution. Original frozen bytes and their SHA-256 remain in the ignored artifacts; the results record both hashes and confirms identical parsed inputs. Inline native/browser screenshots and accessibility observations are in the evaluator tool trace. Local raw artifacts are under `.local/composio-proxy-review/cp06/`, with 22 artifact hashes retained in the results record. The native app, evaluator server and both test tabs were closed.
