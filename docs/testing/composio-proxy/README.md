# Managed integration verification

Use the maintained tests and the CI run for the exact commit under review. This page describes coverage and its limits; it is not a release acceptance result. Product behavior and configuration are in [Connected apps](../../composio.md).

## Maintained checks

| Boundary                                | Reproducible coverage                                                                                                                                                                                                                                                                                                                                                                 | Limit                                                                                                                                                                                             |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Default routing and account continuity  | The five `default Composio adapters:` cases in [integrations.test.ts](../../../tests/integrations.test.ts) exercise actual composition, SDK and service code through a [stateful synthetic backend](../../../tests/fixtures/composio-defaults.mts). They cover fresh desktop, keyless server, managed restart, explicit server key rotation within one project and a foreign project. | Seeded synthetic grants, intercepted HTTP, disabled periodic workers and bypassed model initialization. Fresh routing is not completed OAuth consent; process restart is not a packaged update.   |
| Installation identity and SDK transport | The same test file covers persisted private identities, unsafe filesystem entries, hosted owner separation, signed requests, credential stripping and no execution retries.                                                                                                                                                                                                           | These assertions cover their specified filesystem and transport paths, not every possible secret channel.                                                                                         |
| Reconnect and callback admission        | `integration provider changes replace owned connections only after verified consent`, deferred callbacks and setup-status cases exercise owned attempts, verified account identity, cancellation, stale callbacks and concurrency.                                                                                                                                                    | A changed provider requires reconnect. Same-project direct key rotation preserves verified data; replacing the account clears obsolete polling state and queued work. Provider HTTP is synthetic. |
| Attachment preparation                  | `Composio uploads file bytes before the app consumes its storage reference` and `metering covers capabilities without recording prompts, arguments, output or secrets` cover adapter bytes and selected-account forwarding.                                                                                                                                                           | These are application contracts, not evidence of a real recipient receiving an attachment.                                                                                                        |
| Web and desktop handoff                 | The desktop OAuth, chat app setup and completion-page cases cover owned pairing metadata, handoff, polling, stale responses and terminal states.                                                                                                                                                                                                                                      | DOM and bridge fixtures do not establish acceptance of the installed native app or external provider pages.                                                                                       |
| Desktop profile and update preservation | [Desktop settings tests](../../../desktop/test/settings.test.mjs) cover retired saved keys and the encrypted vault. The [signed update check](../../../desktop/scripts/check-native-updates.mjs), run by [desktop update CI](../../../.github/workflows/desktop-updates.yml), checks a fixture profile and integration signing identity across installation.                          | The signed updater fixture does not run the full app, real OAuth or the production integration backend.                                                                                           |
| Broker enforcement                      | The companion repository's [broker tests](https://github.com/n8n-io/otto-composio-proxy/blob/main/test/broker.test.ts) cover request signatures, replay, owner/account/session selection, browser pairing, file capabilities and local workerd behavior.                                                                                                                              | Run and record the exact companion revision. Synthetic upstream responses and local workerd do not prove the deployed provider contract.                                                          |

Run the ordinary repository checks from a disposable checkout, following [Contributing](../../../CONTRIBUTING.md#checks):

```sh
npm run check
npm run test:integration
npm run build
npm run desktop:test
```

`test:integration` creates its own isolated PostgreSQL and browser fixtures. A focused database case also needs a disposable `TEST_DATABASE_URL`; a skipped case is not a pass. For example, run one scenario at a time with:

```sh
node --import tsx --test --test-name-pattern='^default Composio adapters: fresh desktop uses managed routing$' tests/integrations.test.ts
```

Keep the tested commit, command, runtime, output and failures with the CI run or review evidence. Report controlled tests, native UI observations and live provider checks separately. A successful build or secret scan does not establish OAuth correctness or complete absence of credential exposure.

## Historical records

The earlier CP01–CP07 manifests, inputs, outputs, runners and simulated-consent video are preserved in the [immutable historical tree](https://github.com/n8n-io/otto/tree/e12bf3e30f4823222d23977ead9a060700c97710/docs/testing/composio-proxy). Their committed bytes have not been rewritten. They are retired investigation records, not proof for the current source, and their pass labels must not be reused as release acceptance.

Known limits of those records include incomplete source/time/variant bindings, author-local paths and unavailable private evidence; checks labelled `SECRET` that scanned only selected responses; interrupted replay described too broadly as cancellation; local account fixtures presented as remote grant continuity; and early upload checks that omitted some header, collision-control or cleanup assertions. The historical CP05.v2 runner also cannot guarantee cleanup when its uncaught timeout terminates the process. Deployed catalog and empty-session probes did not complete OAuth or deliver an action. Later tests supersede coverage where stated above; they do not retroactively repair those historical measurements.
