# CP03 provider selection

**Provider-selection and local preservation checks passed on the recorded source.** The complete SECRET gate was not measured; see the [review corrections](review-followup.md). The run used Node `24.21.0`, the actual `createDefaultAdapters`, native settings store, Composio provider and SDK. Source hashes, exact inputs, expected results and evaluator scripts are in the [frozen inputs](cp03.v2.inputs.json); traces are in the [results](cp03.v2.results.json).

| Scenario                                                          | Result | Observed behavior                                                                                                         |
| ----------------------------------------------------------------- | ------ | ------------------------------------------------------------------------------------------------------------------------- |
| Desktop with retired saved key, environment key and custom proxy  | Pass   | Signed requests reach the hosted proxy; saved ciphertext stays unchanged and renderer settings contain preferences only   |
| Desktop restart and different owner                               | Pass   | Restart retains identity; another owner gets a different identity                                                         |
| Server without a key                                              | Pass   | Signed hosted requests; restart retains identity and a separate profile gets a different identity                         |
| Server with explicit key, then rotated key                        | Pass   | Direct requests use the configured key and application owner; custom proxy setting does not override explicit direct mode |
| Server with trusted custom proxy, then another origin             | Pass   | Requests bind their signatures to the selected origin; installation identity remains stable                               |
| Tenant with replacement data root and another owner               | Pass   | Same owner and secret reproduce identity; a different owner remains isolated                                              |
| Server with blank, spaces-only or tabs-only key                   | Pass   | Signed hosted requests with no project-key header                                                                         |
| Existing direct connection after configuration fingerprint change | Pass   | Existing ID, active state, cursor, watch preference and queued event survive against a synthetic owned-account map        |

All 16 final mode variants passed once. They produced 56 independently verified signed requests and eight direct SDK requests. Every variant loaded the catalog and created, restored and deleted an empty synthetic session. The SDK's two version-check requests were intercepted too. Unknown destinations and routes were rejected; PostgreSQL calls were forbidden. Only unrelated model initialization was bypassed.

The whitespace holdout first failed: composition selected direct mode and HTTP normalized the key header to empty. That red remains in the results. Trimming the key makes blank values use the hosted proxy. The unchanged 16-variant `createDefaultAdapters` matrix then passed; the equivalent hosted-webhook change was source-reviewed only. Nonblank explicit keys still select direct mode. No SDK CLI credential fallback was observed.

The database repeat passed all four local-preservation variants at service hash `174fc5b7`. The original missing-fingerprint and changed-fingerprint preflight ran unchanged; its provider does not model project-scoped grants or observe every attempted side effect. Two further variants started with the actual base-release schema, verified the new columns were absent, then confirmed additive initialization preserved every old connection field. Both enabled and disabled watch preferences were respected. All schemas were disposable and removed. Earlier attempts and the original red remain preserved.

There were no live accounts, models, recipients or network passthrough calls. Native encryption was synthetic; the settings store was real. Sandbox constructor configuration was reviewed in source, but this run did not launch a container. These results establish provider-selection and identity contracts, not live OAuth or provider delivery.
