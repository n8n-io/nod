# Silent memory acceptance

Version 3 was frozen on 2026-10-07 for [LAB-535](https://linear.app/n8n/issue/LAB-535), using the supplied `agent-eval-loop` skill. The user rejected repetitive “Got it” replies in the synthetic preview. Routine context updates can stay silent, while actual questions and requests need useful responses. Earlier versions remain historical evidence below.

Supported durable facts still persist automatically. Unsupported or unverifiable candidates are skipped without a write or confirmation. The change must preserve owner scoping, source restrictions, sensitive-topic controls and the owner's choice to disable saving. Memory remains inspectable and editable on the Memory page.

## Version 3 hypothesis and results

Hypothesis: the repetitive acknowledgements come from the preview's unconditional final “Got it.”, not a production requirement. The baseline should show saved notes plus these fixture-authored replies, while an empty final event should already complete without a persisted assistant message or empty bubble. Finding a runtime-generated acknowledgement or a stalled empty-output turn would disprove this hypothesis.

The v2 preview and its fixture confirm this test setup fault. Production already accepts a successful empty final event, omits empty assistant rows, removes the stream and sends no channel reply. The change clarifies that ordinary context can stay silent and repairs the preview; it adds no hard-coded reply filter. The existing application regression now verifies silent base and Portuguese context turns, followed by a substantive answer using `memory_read` on the same thread. This regression covers the existing runtime contract and is not claimed as a failing live-model baseline.

On clean source `deef92ec2db0b9bb01e227d119d15b7e5eea7b75`, all five cases passed across eight turns in 4.134 seconds. Four context-only turns produced zero assistant messages. Both substantive requests received answers from real tool results; stop and resume returned accurate requested-state confirmations. Both expected notes persisted, with zero approval rows or unsolicited memory messages. Saving finished enabled. Evidence: `.local/lab535-ui/showcase-v3-green-summary.json`, `showcase-v3-green-seed-results.json` and `showcase-v3-green-events.jsonl`. The prior fixture acknowledgement failure is preserved in `showcase-v3-baseline.json`.

Browser inspection verified consecutive context messages with no empty bubbles, followed by the useful two-bullet routine summary. The 390-pixel chat retained the same content and usable composer; the desktop viewport was restored afterward. Settings → Memory showed both exact notes, saving enabled and sensitive topics disabled. Screenshots: `.local/lab535-ui/showcase/quiet-desktop.jpg`, `quiet-narrow.jpg` and `quiet-memory.jpg`. The corrected preview remains available locally.

The focused application regression passed with no skips. `npm run check`, `npm run build` and all 635 isolated Linux integration tests passed; the full suite had zero skips and took 99.182 seconds. Evidence: `.local/lab535-quiet-check.log`, `lab535-quiet-build.log` and `lab535-quiet-integration.log`. An independent code review found no actionable issues. These results establish application and rendering contracts; live model response selection remains unevaluated.

## Checks and run rule

Every applicable check is required in the same attempt. Missing prerequisites block a run; a failed measurement is an error. The base case, holdout and regression cases must pass.

| Check       | Observable pass condition                                                                                                                                                                             | Evidence                                                       |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| SAVE        | The exact expected note persists and the turn succeeds.                                                                                                                                               | Actual application routes, workers and disposable persistence. |
| SOURCE      | The reviewer receives owned user messages and the candidate, excluding assistant, fetched, foreign-owner and future content.                                                                          | Captured reviewer input and application regressions.           |
| SILENT      | No memory confirmation, first-save notice, receipt metadata or receipt message is created; the turn does not wait for a memory approval. The deterministic assistant gives only an ordinary response. | HTTP message history, turn state and the real renderer.        |
| FENCE       | An unsupported candidate is not written; execution continues without asking for confirmation.                                                                                                         | Real application tool result and persisted memory.             |
| CONTROL     | Disabled saving and restricted sensitive topics cannot cause an automatic write.                                                                                                                      | Existing application and reflection regressions.               |
| FAIL-CLOSED | A missing, failed, malformed or negative review skips the write without creating a confirmation.                                                                                                      | Application regression with deterministic reviewer outcomes.   |

Run rule: one deterministic attempt per base, holdout and regression on each tested build; the application regression retains its 30-second test limit. The independent HTTP observer allows 60 seconds per turn and records both observation time and persisted turn timestamps because earlier observer reads occasionally stalled after execution completed. This observer limit is frozen before the v2 candidate run. One browser pass checks desktop and narrow chat plus the Memory page, with a 15-minute allowance.

The agent and reviewer are deterministic fixtures with no provider cost. They exercise real routes, workers, storage and memory policy. The fixture's ordinary final response is “Got it.”; it does not claim a save. These runs establish application behavior, not live model judgment. Tests never call a live model, connected account or real recipient.
