# Web interface

`app.tsx` owns authenticated routing and the inspector layout. `components/sidebar.tsx` owns sidebar interactions, modifier hints and shortcuts; `lib/navigation.ts` owns their mapping. `pages` owns views, `components` owns shared controls, and `styles.css` owns the palette/layout. Use `lib/api.ts` for HTTP and `../shared/contracts.ts` and `../shared/account.ts` for wire types. The browser must not import server, runtime, ports, or provider code.

`lib/message-links.ts` accepts only an exact `/apps?connect=<UUID>` setup link from chat. Keep that link in the current tab so the private Apps dialog can return to chat after connection. Do not allow another query parameter, fragment, or redirect target through this route. Token entry stays in the dialog and never enters chat text.

`theme.css` owns the semantic light/dark colors used by shared controls, pages and modals. Dark primary controls use pale lavender with dark text; outline controls use distinct control fill, border, text and hover tokens. Pink remains the navigation accent. Keep content images, PDFs and browser frames unchanged. `public/theme-init.js` selects the saved `otto.theme` value or OS preference synchronously in the document head before app rendering. `lib/theme.ts` handles accepted changes, cross-tab device updates and OS changes. The accepted account theme overrides the device choice without being written to browser storage; System follows the OS even when the device has an older explicit choice. Storage failures must leave the current session usable. `lib/ui-preferences.ts` also contains best-effort sidebar, Inspector visibility and width preferences; denied reads or writes must never prevent navigation or rendering. The account dropdown and mobile top-right navigation menu expose Light, Dark and System; account settings expose preview cards. Standalone secure forms and `/browser` inherit the accepted account theme without fetching app state. Browser and touch icons are real local assets under `public`, declared in `index.html`; preserve `/favicon.ico` as an image response.

Message inspection dispatches `otto:inspect-message`; the app focuses the internal run without adding tasks to the user chat. The inspector is resizable and opens beside chat without forcing the sidebar to collapse; at intermediate widths, it stacks below the main view when the sidebar is expanded; `/dev` opens it directly.

At widths of 640 px or less, a compact top bar exposes Chat and a top-right Navigation menu. Put Chat, Goals, Schedule, Apps, Channels, Vault, account actions, theme controls, enabled Inspector and Restart setup inside that menu; remove bottom navigation and hide collapse controls. Preserve native modified link actions, current-page labels, Escape/outside dismissal and focus return. Close the menu after navigation or a desktop resize. Every private request uses `lib/api.ts`, including chat submissions and screen frames. It attaches `X-Otto-Account` as an expected-principal guard, never a tenant selector. Account changes and sign-out abort pending requests, clear page caches, remount private views and clear drafts/frames. Session and account responses are fenced against stale identity; mutations serialize and accepted writes fence older session reads. An active 401 hides private views. SSE binds `/api/events?account=<accepted user ID>` and closes on unmount. `lib/app-events.ts` requires an accepted session owner, derives it when omitted, and always includes the expected-account query. It preserves native `CONNECTING` retries and replaces terminal `CLOSED` sources with one pending retry, backing off from one second to at most 30 seconds. Session refresh runs independently on errors; fence replaced sources, timers and late events by the accepted account and session epoch. The server remains responsible for ownership, capability and ongoing session checks. Never persist account data or auth tokens in browser storage, and never log private values.
