# Provider adapters

Implement the smallest applicable interface in `../ports`. Factories accept credentials and configuration explicitly. `../server/composition.ts` chooses implementations. Provider SDKs, protocols, transport parsing and vendor defaults stay here.

`composio/verification-email.ts` provides the private verification-email read capability. Use only fixed Gmail list/get endpoints through the selected connected account, with recipient, sender-domain and time filters, at most five messages, bounded MIME decoding and cancellation. Require visible recipient headers and Google's first authentication result with DMARC pass aligned to the From domain; reject uncertain parsing and pagination. Return mail only to the trusted server matcher, never a model session, tool catalog, event store, usage payload or error message. This path does not send mail or manage accounts.

Direct OAuth uses the injected Vault grant port for pending and active secrets. It moves valid older ciphertext at startup and skips ciphertext it cannot decrypt or parse. A Vault write or database failure stops startup so the migration can be retried. Adapters must not import feature modules or runtime implementations. Normalize errors and output shapes. Never expose keys, OAuth tokens, raw SDK sessions or plaintext vault contents to the runtime, model or web client. The key-store port returns key bytes only to trusted vault and channel-settings services. SDK state that must persist needs an explicit reference and migration policy.

`public-web/search.ts` calls the Pi Web Access search engine. It returns short public source results and a fixed error. It does not load the Pi extension or expose its file, command, or browser-cookie functions as tools. The model can use the task browser to read a source page.

`composio/integrations.ts` resolves missing discovery schemas through the existing session's fixed `COMPOSIO_GET_TOOL_SCHEMAS` metadata endpoint. Hydrate at most 20 advertised supported-toolkit tools in one bounded request, with no retries or application execution. Require complete matching schemas, preserve full schema bytes and remove resolved references before returning discovery. Keep malformed references, partial results and provider errors fail-closed in `composio-discovery.test.ts`; transport fixtures do not establish live account access.

`direct/plugin.ts` loads only fixed bundled Agent Plugins v1 packages. `direct/oauth.ts` uses the private key-store capability for owner-bound OAuth state and tokens in the local or hosted tenant SQL namespace. `direct/mcp.ts` owns remote transport, while `direct/integrations.ts` maps approved reads to tools and reads Notion user identity from the `notion-get-users` result list. Keep account policy, callbacks, and task handoff in the server feature. New endpoints need an explicit package and approved action mapping. Do not pass package headers, tokens, or host credentials to the workspace or model.

`chat-sdk/settings.ts` verifies account details without changing provider state. Its separate registration method applies the exact encrypted configuration already persisted by channel settings. Telegram retries must reuse the saved webhook secret and retain pending updates; a lost response does not justify generating another secret or restoring unknown remote settings. Provider fixtures cover this sequence without real accounts or message delivery.

`openai/relevance.ts` uses the installed OpenAI model catalog without network discovery. Send `reasoning_effort: none` only when the selected model declares that off value. Non-reasoning models omit reasoning parameters; models with unknown capabilities omit optional reasoning and sampling fields. Keep the shared default in `shared/model-defaults.ts` and cover model overrides in `provider-adapters.test.ts`.

Before swapping an adapter, follow [replacing modules](../../docs/replacing-modules.md). Test its protocol mapping separately from product behavior. Browser work must retain exact-origin credential checks, observation locks, bounded output and cleanup. Workspace subprocesses must not inherit provider keys. Review [security](../../docs/security.md).

`pi` translates completed assistant message usage into the provider-neutral `model_usage` event, including turns that only call tools. Preserve separate cache token counts and label SDK costs as estimates. Never invent rates or count persisted history again. Include a distinct failed attempt only when the SDK reports usage for it. These events exclude separate compaction, cache-warming, speech and browser-provider charges. Keep deduplication and retry behavior covered by `pi-agent.test.ts`; these fixtures do not verify a provider bill.

`pi/conversation.ts` implements the conversation-routing callback through `ModelRuntime.completeSimple`. It uses the shared GPT-6 Luna or Claude Haiku 4.5 catalog default, an explicit model override when configured, server credentials, in-memory configuration, no tools, no session, no catalog refresh and no stored conversation history. Keep the input/output caps, shared five-second budget, zero retries and strict decision union. Eligible and blocked candidates share an eight-outcome cap. A continued outcome must match a supplied candidate; continuing a blocked outcome preserves that decision for the server to reject, never converts it into fresh execution. Candidate text and bounded recent conversation are untrusted data; routing never grants permission or bypasses waits and revisions. Preserve explicit null outcome provenance for ordinary conversation, omit task/message IDs, and bound the extra context to 12 messages of 1000 characters. The server owns fallback and routing policy. The optional usage callback records one `relevance/conversation_route` operation with only SDK-reported tokens/cost estimates. Cover the whole call, including lazy initialization, with fixed failure codes and optional HTTP status; never serialize provider errors or causes. Preserve cancellation and avoid duplicate observations from late completions. The server can retain strictly validated taskless/tool-less failure metadata with Inspector disabled, without retaining model inputs or outputs. Test these boundaries with `pi-conversation.test.ts`; no live provider call is required. The [earlier C22 probe](../../docs/testing/results/2026-09-25-c22-routing.md) records the previous routing investigation; a small successful probe is not an intent-recognition guarantee.

Routing failure categories describe the observed phase, not the responsible party. `transport` means the request failed before response headers arrived. `response_processing` means headers arrived but completion failed, including a non-2xx response, body-stream failure, parsing failure or provider error event; it does not establish a provider fault.

`agent-browser/login.ts` owns trusted login inspection and method selection scripts. Scope detection to an active visible dialog or focused form, clear prior markers, and deduplicate equivalent OAuth controls. Ambiguous fields or forms stay unsupported. `credentials.ts` owns typed secure entry. Support identifier, password and one-time-code stages using observed fields; never request those values through the model. Method selection must recheck the origin and current control. A single visible group of four to eight sibling verification inputs with a one-character limit uses one OTP selector. Recheck the group size, type, origin and visibility before entering any digit; unrelated or ambiguous groups remain unsupported. Portuguese submit labels include Entrar. Passkeys and separate-window secure entry remain unsupported.

Credential submission checks fresh visible rejection feedback for at most two seconds while observations remain locked. Only bounded status and fingerprints leave the feedback script, never error text or entered values. Distinguish a new error or replacement document from a stale alert, and require the credential stage to remain present. `submitted` means entry occurred, not successful authentication. `rejected` lets Vault rotate the one-use form without resuming or saving bad input. Keep delayed rejection, password/OTP correction, unchanged expiry and stale-token tests in `vault-rejected-login` and feedback visibility/freshness checks in `credential-feedback`.

`agent-browser/index.ts` sends warm browser commands once through the private daemon socket with an absolute deadline. Initial launch still uses the pinned native CLI. Cancellation or timeout keeps the queue fenced until close is acknowledged; do not retry an uncertain command. `tests/browser-transport.test.ts` uses real local Unix sockets to cover the wire lifecycle.

`agent-browser/downloads.ts` bounds authenticated browser file capture to 12 MiB and validates private regular files, encoded bytes and metadata. `Computer.download` uses the same task locks and private bridge as other browser actions. Cross-origin attachments use native capture in the existing task download directory; preserve prior files and renamed partials, and clean new files only after completion or confirmed browser shutdown. Do not automatically retry a redirect blocked by page fetch permissions. Never expose a model-selected filesystem path, browser cookies or profile to the workspace or model. Publication belongs to the trusted task callback and originating channel. Keep native cookie-protected capture in `browser-download` and runtime-to-owned-HTTP/Telegram delivery in `browser-download-delivery`; fixture transport acknowledgement is not live delivery.

No-target capture on a non-PDF page waits at most five seconds for the sole native download to finish. Preserve cancellation, directory identity, regular-file and size checks throughout the read-only wait. Multiple entries, including completed-plus-pending files, remain ambiguous. Never re-click, re-fetch, navigate or delete files to resolve completion. Keep the held-response native regression separate from ordinary public-file production acceptance.

`agent-browser/manual.ts` validates browser takeover input. `index.ts` reserves control before awaiting the per-session queue and blocks agent actions, credential injection, login inspection and method selection until release. Recheck locks inside queued work. Send typed text only through the private daemon socket, protect the focused editable field, and mask screenshots/observations. Release, close and the fixed 30-minute expiry invalidate pending input; expiry does not resume the task. Known protected fields remain blocked through alternate model selectors. Socket protocol mappings must match the pinned agent-browser version, including recovered-session click, fill, attribute and scroll commands. `hold` retains a waiting browser only to its bounded expiry. New launches are limited to four tracked live sessions per Computer. Capacity allocation is serialized and evicts the oldest idle, unheld session while retaining its profile and masked last-known frame. Queued or running operations, injection, manual control and native sign-in are protected; if every slot is protected or cleanup fails, a new launch fails without exceeding the limit. Recovery of pre-existing daemons and multiple worker namespaces are separate from this per-Computer launch bound. Cover capacity, close failures and concurrent reservations in `browser-capacity.test.ts`.

`agent-browser/screens.ts` stores masked screenshots and bounded metadata in private files. The optional `screenStatus` describes the preceding `screenshot` result as live, last-known or unavailable. Inspector recovery must not navigate, launch a browser or replay credentials. The socket recovery path is bound to agent-browser 0.38.1's protocol; keep its mapping tests when changing that dependency. A restarted credential-bearing session uses its cached image until an explicit reopen because secret redaction values stay in memory only.

Mark current browser activity when an accepted action starts, before awaiting navigation or browser commands. Long-running work must be discoverable by the inspector, and an older action finishing later must not override a newer accepted action. Preserve manual-control priority and rejection/cancellation checks before changing activity. The held-navigation fixture in `runtime-adapters` covers this ordering.

Known Chromium network navigation failures use the fixed `BrowserActionError` code. Persist only the validated destination without query or fragment and the failed state; never expose the raw CLI error. A failed page has no usable login form or current screenshot. Snapshot returns a bounded diagnosis with no controls, including after restart. An explicit new open closes the failed session before using a fresh proxy and clears the failure only after navigation succeeds. Keep HTTP(S)/userinfo validation and exact-origin secure-entry checks; cover this behavior in `browser-navigation.test.ts`.

`agent-browser/network.ts` closes the browser side of a CONNECT tunnel when its upstream closes without a readable end, including the 60-second idle timeout. Normal upstream completion must still flush pending response bytes. The acceptance fixture tracks its pending and connected upstream sockets and closes them during shutdown. Keep both tunnel directions, slow readers, fixture chaining and pending-connect disposal covered by `browser-proxy-lifecycle.test.ts`. These local socket checks do not prove the cause of a live website's stalled request or change unrestricted browser destinations.

Run the focused browser/vault checks with `npx tsx --test tests/browser-login.test.ts tests/browser-manual.test.ts tests/browser-recovery.test.ts tests/takeover.test.ts tests/runtime-credentials.test.ts tests/runtime-adapters.test.ts tests/vault-staged.test.ts tests/vault.test.ts`. The vault tests require `TEST_DATABASE_URL` for a disposable schema. The staged DOM/socket fixtures and isolated synthetic Chrome pages do not prove a live provider login works.

`chat-sdk` advertises Telegram attachment support and maps byte-backed PNG/JPEG/WebP images up to 10 MiB to photo uploads; other files use document uploads. It accepts no remote attachment URL or filesystem path. A logical delivery can use multiple provider requests; preserve an uncertain result after any partial failure. WhatsApp attachment delivery is not implemented. Test these mappings with `channel-artifacts.test.ts`; its fetch fixtures are not real recipient delivery.

`container-browser/config.ts` selects headed Chromium for ordinary workspace browsing. On Linux, `index.ts` starts a separate private Xvfb display for each launched task and passes only that display's environment to the browser CLI. Reuse the display while that browser lives; close it only after confirmed browser closure, including eviction, cancellation, native handoff and disposal. Failed browser closure keeps the display available for cleanup retry. `browser-headed` covers launch environment, task separation, handoff, interrupted launch and failed close. Headed automation still uses CDP and is not a claim that a provider accepts automated sign-in.

`agent-browser/sign-in.ts` opens the same container `/usr/bin/chromium` and private profile without automation or debugging flags. `desktop.ts` owns a private authenticated Xvfb display with no TCP listener, bounded in-memory screenshots and fixed xdotool input with text on stdin. Keep sanitized environments and bounded owned-child shutdown. Completion requires normal quit and confirmed process/display cleanup; forced cleanup cannot resume. Empty workspace sessions may launch about:blank; close, failed launch and expiry release their capacity reservation and pending state. Only active manual leases take priority over newer browser activity. `index.ts` blocks ordinary observations/input while sign-in is pending, while separate owner-only native methods serve transient frames and input. The automated display closes before native launch; continuation creates a fresh automated display. Persist the pending fence and restoration preference across restart, redact the return path and never reopen after cancellation or expiry. Version-resolution fixtures remain factory tests; production never falls back to host Chrome. Cover helpers in `browser-desktop`/`browser-sign-in` and adapter races in `browser-sign-in-handoff`; fixtures do not prove real provider acceptance.

`container-browser` implements the host Computer through a fixed Docker stdin bridge. Its persistent worker owns the existing browser adapter, proxy, profiles and screenshots inside a separate trusted browser container. `container-browser/config.ts` selects the fixed native Linux agent-browser binary for the container architecture, avoiding the npm launcher wrapper. Interrupted browser commands must close and drain that exact daemon session before cancellation completes; failed cleanup retains the task lock. Keep the private `/data/control.sock` at mode 0600, application namespaces derived from data-root hashes, strict method/input bounds and namespace-specific disposal. Never expose the socket, profile volume, desktop or CDP to the untrusted shell workspace, or fall back to a host browser. Credentials and input travel only over stdin; replies use bounded private frames and fixed public errors. Cancellation must reach the worker and await terminal acknowledgement before the host continues; missing acknowledgement fences further actions. Premature disconnect quarantines the worker namespace until pending work and Computer disposal finish, including when the host restarts. Explicit disposal drains only its namespace. Each namespace permits at most 32 pending calls; the worker accepts at most 256 connections. Cached activity and screen metadata cannot regress when older replies arrive. Native sign-in frames use separate owner-only methods and never enter the normal screenshot cache. `container-browser.test.ts` exercises the real Unix socket and bridge with synthetic Computers; it does not prove Docker, Chromium or a live provider. The worker's injectable factory supports isolated test scripts without a production environment switch or certificate override.

The workspace uses the normal Compose network with no Otto egress firewall or network-guard sidecar. Keep its unprivileged user, dropped capabilities, resource limits and restricted mounts. Network reachability follows Docker and host routing; do not claim LAN, metadata or IPv6 filtering. The acceptance harness obtains its one attached network from Docker inspect, validates the name and attachment, and reuses that network for its disposable workspace; it does not accept a user-supplied network or join a host/container namespace.

Workspace commands use `docker/command.ts`, a fixed Python supervisor started through Docker exec. Commands and file contents travel on stdin. The supervisor owns a process group, enforces the timeout/output limit and acknowledges completion or cancellation only after that group has stopped, including children left after their shell exits. The host waits for this acknowledgement; a lost connection or missing acknowledgement fences the adapter until restart and cancels and drains other pending commands. Disposal also aborts and drains pending commands. `docker/index.ts` reads publication and image-attachment bytes inside the container through `Workspace.readArtifact`: walk directory descriptors with `O_NOFOLLOW`, accept a regular file only, and bound its size and final read. Never resolve an untrusted workspace path into a host read. The workspace remains a single-owner shell environment, not isolation between arbitrary commands or task directories. A connected CLI call runs under the separate `otto-connected` user in local Docker and hosted E2B. Its Vault token reaches only the selected program environment. The supervisor uses a temporary home directory and removes it after an acknowledged call. The ordinary shell has no Vault read path. A selected CLI can still send or copy its token.

After an acknowledged normal completion, `docker/index.ts` represents a nonzero child exit as `WorkspaceExitError` from the computer port, with an integer exit code and bounded combined stdout/stderr. The runtime may recover this result only for the shell tool. The error's own message remains fixed; command diagnostics belong in its private output field. Supervisor cancellation, timeout/output limits, malformed responses and uncertain transport failures retain `WorkspaceCommandError` and their existing drain/fencing behavior.

Login inspection chooses a focused candidate-containing form before inferring a generic identifier. Multiple unfocused forms remain ambiguous. Reject named, inherited or non-current browsing targets both when advertising a method and immediately before secure submission. Same-origin embedded manual fields use their actual focused document and retain field/text masking across at most sixteen documents; inaccessible frames use the native sign-in handoff instead of weakening protection. Ordinary cross-origin page content remains observable before secret entry; unreadable frames are hidden when a protected value has been collected. This is credential masking, not a prohibition on reading the user's authorized private page content. Browser recovery uses streaming UTF-8 decoding. Host browser activity belongs to accepted actions, not later screenshot polls; disposal cancels and drains bridges that have not yet reached the worker before disposing the namespace.

Telegram polling must clear failed offset initialization so a transient database error can recover on the next poll. Keychain creation is serialized within its adapter; a competing process winning creation is reread rather than replacing its key. Public preview images accept bounded static PNG, JPEG and WebP only. Reject PNG animation chunks, truncated chunks and trailing payloads; do not advertise GIF. Existing public URL and redirect checks remain separate from unrestricted workspace browser networking.

Shutdown must attempt and drain every owned session before reporting a cleanup failure. Pi abort failures must not skip session disposal. Failed disposal remains retryable. The browser keeps its private proxy available until all sessions close, so a failed close can be retried. Container host and worker cleanup retries retain the unavailable namespace fence until the prior Computer is fully disposed; a restarted host cannot bypass that fence. Cover these failure paths with `pi-agent`, `browser-headed` and `container-browser`.

`e2b/index.ts` composes the same browser bridge client and supervised command workspace over E2B SDK 2.51.0. Factories bind one verified owner and receive credentials, one combined template ID and a durable `ComputerAllocationStore`. Browser, workspace, and connected CLI share one `computer` allocation, with separate Linux users and a checked private-browser boundary. The network guard applies its workspace rules to both the task shell and connected CLI user. `e2b/allocation.ts` owns versioned leases, generation-preserving reconnect, confirmed pause and persistent uncertainty fences. Never automatically replace a leased or uncertain resource, including an expired lease. SDK keys and traffic tokens stay inside the trusted provider. Template builds in `deployment/e2b` copy only required source/package files or the generated supervisor. Keep `e2b-adapters` and `e2b-client` fixtures alongside the shared browser/workspace suites; these are local protocol checks, not live E2B or provider sign-in proof.

`cloudflare-computer/index.ts` composes the same bridge and supervised workspace for tenant mode only. Bind the canonical owner UUID to `sk-` plus the first 24 SHA-256 hex characters and capture the positive runtime generation at construction. The fixed private `http://otto.computer` transport includes that generation and the browser/workspace role on every request; owner authority comes from the hosting Worker, not a caller-supplied owner header. Keep separate keyless role images and preserve uncertainty fences, cancellation drain and retryable browser disposal. An unused adapter must dispose without allocating a computer. The Worker owns computer startup, idle checkpoints, restoration and confirmed stop; the Node adapter must not recreate a fenced computer itself.

Cloudflare browser requests allow 300 seconds plus a 30-second cancellation drain. Supervised workspace commands retain the Python limit of 120 seconds; `transportGraceMs` extends only the host acknowledgement watchdog for startup, restore and durable checkpoint work. It defaults to zero for existing transports, accepts integer values from zero through 300,000 and is 300,000 for Cloudflare. `cloudflare-computer/entrypoint.mjs` exposes only internal `/health` readiness, waits for an actual browser control-socket connection, and leaves workspace state empty until the Worker restores it. `checkpoint.py` transfers bounded manifests and tar bytes with SHA verification; restore must preserve an absent or unchanged target on failure. Browser profiles and workspace/tools use distinct roots and must never share an image or checkpoint.

`better-auth` handles only Google identity, encrypted OAuth persistence and session revocation; raw provider endpoints and tokens are not exposed to the client. `better-auth/avatar.ts` reads only HTTPS Googleusercontent URLs, checking every manual redirect, without forwarded cookies or credentials. Bound the full operation to five seconds and two MiB, accept only matching PNG/JPEG/WebP bytes and MIME types, and keep source URLs private. `raster-image.ts` shares bounded static image validation with public link previews. It checks container structure, dimensions, PNG CRCs, JPEG marker/scan termination and WebP chunk layout; it does not decode pixels. Reject trailing payloads and animated formats, and keep synthetic valid-image and malformed-container regressions in `raster-image.test.ts`.

`object-storage` implements private filesystem, authenticated infrastructure-broker HTTP and self-host S3 storage behind `PrivateObjectStore`. Composition must scope the adapter to one owner and environment. Cloud actors use only `http://otto.storage/v1/objects/<encoded-key>` and send the immutable process generation in `x-otto-generation` on every request; never give an actor shared R2 credentials or expose this broker as a public route. The generic HTTP adapter keeps generation optional for other local transports. Bound every object to 16 MiB and preserve conditional writes. R2 broker conditional DELETE is unsupported and must fail rather than silently delete a newer object. A failed metadata insert can therefore leave a private orphan for operator reconciliation. Filesystem CAS uses exclusive lock files; a crash-held lock requires operator reconciliation, never an automatic stale-lock takeover.

`../ports/object-storage-validation.ts` defines the shared canonical key grammar, byte limits and fixed storage errors for every adapter, including PostgreSQL. Validate read limits even when an object is absent. Filesystem failures must not expose host paths; retain the distinct conditional-write conflict error. Hosted filesystem roots include the immutable owner UUID beneath the configured operator root.

`pi/checkpoint.ts` restores cloud sessions into an in-memory Pi SessionManager. Await conditional durable snapshots before tool side effects, after their result receipts, at turn boundaries and before publishing final completion. Each snapshot has a fresh revision so identical content cannot bypass writer fencing. An unresolved tool marker blocks automatic resume; completed receipts repair a missing ordinary tool-result entry after a crash. Never replace these barriers with asynchronous event subscriptions. Private transcripts remain bounded to 15 MiB; a storage failure or size limit stops work. Provider credentials and secure-entry values must remain outside transcripts. `Workspace.writeArtifact` transfers owned bytes over the supervised transport in bounded chunks, then atomically publishes the task file; it does not expose host paths or bypass cancellation/drain.

E2B allocation heartbeats renew both the durable lease and a running sandbox timeout. Track acquired command handles: idle pause is allowed only after all handles finish, and requests arriving after 45 minutes of continuous runtime wait for a drained pause/resume cycle. The default two-minute idle pause retains owner/resource/generation and explicitly resumes on the next request. SDK creation sets timeout auto-pause and disables traffic auto-resume. Do not kill/recreate a computer to work around runtime limits. A provider-reported already-paused result confirms pause; failures remain fenced and cleanup retryable. The 180-second SDK command bound applies to each short-lived bridge/supervisor request, not the persistent browser worker.
