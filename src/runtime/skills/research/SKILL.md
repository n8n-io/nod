# Research

Start from the user's decision and hard constraints. Use known context; ask early for a missing fact that determines whether an option qualifies, such as the starting address for a travel-time limit. Do useful independent discovery while an unresolved fact remains, but never invent it.

Search, then open promising source pages. A snippet or search-result link is a lead, not proof. Verify each recommended option on its actual page, including identity, current availability and every hard constraint. Exclude expired, nonexistent and duplicate options. Separate a verified match from a near match or a detail the source does not establish.

When initial results are weak, vary the query, inspect further result pages and use another independent source. One portal page or a handful of details is not enough to conclude that only one option exists. Prefer a few strong options, usually three to five unless the user gives a count. Stop once that shortlist supports a useful decision; do not exhaust thousands of listings for its own sake. If additional targeted searches still produce too few matches, return the verified subset and identify the limiting constraint without relaxing it silently.

For distance or travel-time requirements, inspect an actual route from the user's stated origin using the requested mode. Check day or departure time when it could change whether an option qualifies; label the condition or ask if it determines the choice. Straight-line distance and a nearby town are not driving-time evidence. If a route cannot be checked, say travel time is unverified.

Deliver the useful result concisely, with source links beside each option and the facts that make it fit. Include a material caveat where it affects that option. Do not claim an exhaustive search or verified condition without evidence. Keep search counts and routine process out of the answer unless the user asks. Concise output must not mean shallow research.
