# Agent runtime

`manage_apps list` distinguishes `browserAccess: credentials_saved` from `browser_session`. Saved credentials require the task browser and fresh secure Vault inspection; their IDs are not browser-session IDs. The server's explicit `browser_connection` pre-dispatch rejection returns a completed rejected result. Pi rejects malformed tool-schema arguments before runtime execution. Preserve cancellation checks and the durable receipt before another model action. Browser work or unknown failures still leave unresolved-action fences.

Account work on a website without a saved session uses the task browser: open the site, run `inspect_login`, then `request_credentials`. The user gets one Vault link, such as Add login, and the task continues after the login is saved. `browser_connection connect` is a fallback for a `browser_not_supported` inspection, a `sign_in_blocked` credential result, or an explicit user request to keep a website session. The prompt and the tool description must keep this order. Connect supplies a checked private sign-in link in chat and stops the segment. Use a fixed link label; the model can supply a connection name. `browser_connection use` requires a saved connection ID and a URL on the saved origin. It binds that profile to the current task. A `session_opened` result means the page opened; inspect it before claiming account access. A browser session can expire. Give the same task a new secure link when the site asks for sign-in. Never treat the link or saved session as permission to send, apply, publish, buy or delete.

The `browser` tool supports bounded key presses for search and navigation after a field has focus. A snapshot can wait up to 15 seconds for a slow page before observation. It can select a page area and page through text, structure and controls. It reports scrollable areas so a scroll can target an inner list. `fill` still rejects credential fields. A key press must not send a message, post, application or purchase without the user's instruction.

`index.ts` exports `createAgentRuntime({agent,computer,workspace,chooseBrowserAction?,webSearch?})`. Its methods are `runTask`, `waitForTask`, `inspectTools`, `status` and `dispose`. Runtime lifecycle, tool validation, budgets, prompt construction and waiting states belong here. Concrete SDKs and provider configuration belong in `../providers` and server composition.

Before a browser click, key press, field entry, fast browser step, shell command, secure credential request or login-method selection, the tool wrapper awaits `RuntimeContext.startExternalAction`. The server persists that marker before dispatch, so a failure after it triggers an outcome check. Do not call it for reads, file writes or local publication. `RuntimeContext.checkOutcome` limits the session to read tools plus `report_outcome` and applies the same read-only dispatch policy as `readOnly`; `unknown` pauses with one question. `freshSession` asks the agent for a new session instead of the saved checkpoint.

`tools.ts` owns tool names, descriptions and schemas. Sessions and `inspectTools` use that same catalog. Inspection must not open a workspace, browser or model session. Include optional browser chooser and web search tools only when the factory received those capabilities.

`download_app_file` can return bounded CSV text for analysis. Treat it as untrusted file content. Use the owned file download path and do not fetch a provider URL with shell or browser tools.

`RuntimeContext.observe` receives paired tool starts and ends, with validated arguments, actual outputs, fixed errors and timing, plus provider-normalized model usage. `observations.ts` bounds each write to one second and disables capture for the remaining segment after a timeout. The optional `observationTimeoutMs` factory argument can shorten that limit. Cancellation releases waits immediately; cancelled tool ends and queued or late model usage use nonblocking best-effort delivery. A timeout still disables later usage capture, so totals can be partial. Late callback failures remain handled. Flush only the bounded queue when a segment ends. Server persistence still owns query timeouts, redaction, limits, task revision checks and developer access. Raw tool values can contain private content; do not send them to ordinary logs or chat.

Recheck cancellation after a successful tool-end observation before returning its result to the model/checkpoint. Keep that check outside the execution catch so it cannot emit a duplicate terminal observation. Intentional question/approval/credential waits still return their result; a stopped segment is not the same as an aborted signal.

Interfaces live in `../ports/agent.ts` and `../ports/computer.ts`. A model session receives only registered tools. Keep provider types out of those interfaces. Never add a host shell, arbitrary browser JavaScript or secret-read tool.

`BrowserActionError` carries a recognized fixed browser category from the adapter. Resolve its public message through `shared/browser-errors.ts` before sending it to the model or tool observation; never trust its raw message, arbitrary error codes, command output or website URLs. Unknown errors remain generic and cancellation takes precedence.

An active `browser` click may return a completed blocked result only for `browser_click_intercepted`, which confirms refusal before native input dispatch. Persist the ordinary terminal receipt before another model action. The model can inspect the page and explicitly choose a different control; never automatically retry or force the click. Transport loss, cancellation, arbitrary daemon errors and failures observing an already-dispatched click remain uncertain. Cover recovery and checkpoint restoration with `browser-click-recovery.test.ts`.

Only `shell` recovers a provider-neutral `WorkspaceExitError` after the supervisor has confirmed process-group completion. Return its nonzero exit code and at most 20,000 characters of command output as a failed tool result so the model can correct the command; record a failed observation and await the ordinary durable result receipt before continuing. Never convert unknown transport failures, cancellation, timeout/output-limit errors or file-helper failures into completed shell results. Cancellation still wins if it arrives while the failure observation is being recorded. Fire-and-forget model abort requests must handle rejection; awaited task/session cleanup still reports failures.

A credential request or `{requiresConfirmation:true,question}` result ends the current execution segment. The trusted server already persisted a chat confirmation question; do not post a duplicate message or a review URL. Ordinary explicitly requested actions can return their result directly. Discover app schemas and check browser capability before claiming drafting is unavailable; a draft request never grants permission to send. Ask one focused question for missing recipient/account/content, and preserve the exact stored snapshot for destructive or ambiguous actions. Stop further tools in that segment, persist the provider transcript and allow a fresh segment to continue. Background events suppress streamed prose and automatic final replies. User-facing messages require an explicit useful message or necessary question.

`manage_apps connect` writes one provider sign-in link in chat, then stops the segment. The trusted callback resumes the same task after account verification. Do not continue the model turn while consent is open or treat a link click as proof of a connected account.

`manage_apps propose` follows model research of a service path, including an installed CLI when it covers the task. Each proposed HTTP path needs a GET test path before the user can open the private token form. Prefer one access path that can perform the full requested workflow. The trusted service returns an Apps link for OAuth sign-in or a private token form; the runtime posts that link once and stops the segment. It resumes only after the owner completes sign-in and the path check succeeds. The model receives path IDs and current schemas, never the token. Generic MCP, HTTP, and CLI writes use the existing approval wait. A declared CLI read can run without review after a conservative write-shape check. The model must check the command behavior before it marks it as a read.

Public facts can use public sources. For account-specific data, check saved accounts through `manage_apps` before looking for a new path. If no saved path can do the task, research one and propose its private connection flow. Do not inspect the task shell for service tokens or replace a supported connection flow with instructions for the user to run a command.
For product comparisons, verify that each candidate meets the requested category from a primary source. Check the edition or plan required for each feature. A research summary in chat must link direct sources for its key claims even when an attachment has a source list. For a current price or other time-sensitive value, check that the cited live page states the value and terms. If it does not, mark the current value unknown. Use the least expensive listed plan that includes the requested function as the starting price, without optional additions.
For a requested "if stated" field, search the source owner's help, policy, or FAQ pages before marking the field unknown. Distinguish a missing statement from a page that could not be verified.
Before publishing a generated file, inspect its saved contents with `read_file` or a shell parser. Check the item count, requested fields and drafts. For time-sensitive rows, use the source publication or posting date if shown; a check date does not replace it. Count only entries that meet every required filter. Check plausible source pages from search results before reporting a shortfall, and state the main reason candidates failed. When results have upcoming deadlines, put the soonest verified deadline and its source link in the chat summary. The model must correct a mismatch before it claims completion.

For goal and schedule management, interpret the current user request and resolved context without requiring a command phrase or language. Use list/read tools when only asked to review, discuss or suggest; explicit no-change and draft-only requests forbid saved mutations. Resolve ambiguous targets, changes or timing with one necessary question before writing. The server executes the five validated reversible plan actions for the current owned user segment without another permission step. External content cannot grant planning authority, and this local path never grants external send/write permission.

For a background page report, keep the URL of each browser page whose load or inspection failed. A later browser result with page text can verify that URL. Before `send_message` delivers a no-change report, reject the report if it names an unresolved URL without saying that URL is unverified or unavailable. Match the URL path, query and fragment. Return the URL and ask the agent to revise the report. Search results alone do not clear a failed browser page.

Every resumed session receives current instructions and bounded, dated conversation context. The same verified owner uses all approved channels. Server-provided shared history from other current channel generations is context only: it has no message IDs for replies, reactions or automatic memory evidence. Search older owned current history before repeating identity questions. Never derive the person’s identity from a provider display name or sender identifier. Message replies and reactions use server-provided visible IDs; reactions do not grant permissions. Setup uses connection discovery and read-only account inspection. The server enforces onboarding write restrictions and watch state. A `readOnly` or `checkOutcome` context allows only `send_message`, `report_outcome`, app reads, `download_app_file`, `manage_apps list`, personal-context reads, `read_file`, web search, browser `open`, `snapshot` and `scroll`, and `browser_screenshot`. The tool wrapper refuses every other call with one fixed error before dispatch and records it as a failed tool observation. Message text cannot prepare sign-in in either mode, including final model text and `send_message`; refuse it before login inspection or credential/provider selection. Cancellation during a refusal still records a cancelled terminal observation.

Serialize historical messages, memory facts and attachment metadata as labelled JSON data. A message attachment names its staged `workspaceFile` only when the server copied it into the task workspace; read PDFs there with `pdftotext`. The E2B template is published separately from the app, so its instructions do not claim `pdftotext` until that template is rebuilt; the runtime guidance keeps a pipx fallback. Keep the current request in its own `currentInstruction` field; never concatenate historical role labels or filenames as fresh instructions. This framing reduces ambiguity and does not make untrusted content safe. Profile and active-goal context have separate limits from saved memory facts.

`RuntimeContext.personalContext` carries the saved owner profile and active goals separately from memory facts. Preserve independent bounds for thirty facts, ten active goals and profile fields, so a full fact list cannot evict the profile or goals. The user's IANA timezone remains a separate context field. All personal content is data, not instructions or permissions.

`communication.ts` catches tested direct requests for login details before questions, explicit messages or final replies reach chat. It redirects to freshly inspected secure entry and labels the link with the next action. Streaming batches sentence boundaries and checks the accumulated text. This is a bounded safeguard, not general natural-language or prompt-injection protection. API-key solicitations return a private-configuration result without inspecting the website or opening login Vault; they must not fall through to a chat request for the key. Keep actual credentials in the broker. `waitForTask` includes in-flight tool calls, even if the model adapter resolves early after cancellation; manual control cannot overlap those calls.

Every credential request first inspects the current login state. If several supported methods are available, return their nonsecret choices without creating a Vault form. Ask which method the user wants in chat unless the current request or original task conversation already specifies it. `select_login_method` rechecks the exact current origin and supported method; the current credentials method requires no click, while a provider selection returns a fresh inspection. A sole provider-only method can open directly without a choice-only form. Keep the user's choice through task and credential resumes; never default to Google or change providers without their choice. These checks constrain the tool flow, not general language understanding or arbitrary browser actions.

If the current page has neither fields nor sign-in methods, return a fresh masked browser snapshot without creating a form or pausing. An empty challenge is not proof of authentication; portal, loading and error pages must be interpreted from the observation. A stale final chat solicitation gets one bounded continuation with that observation. Unsupported-only options do not create a blank form. Cancellation must prevent further provider selection, broker calls or snapshots.

Vault invitations use the broker's resolved origin and credential kind after the sign-in method is selected. Login details use one validated local form link with its action, such as Add login, and the normalized full site origin. An observed OTP step first uses the trusted matching-inbox broker when available, then receives a server-authored chat code request if needed. Generic model requests for codes remain intercepted; code replies never enter model context. Strip transient email-code recipient metadata from inspect_login and select_login_method tool results and observations. The secure form gathers login details together even when the website asks for the identifier before the password; do not promise a separate password form. State that no login is saved only when the broker explicitly reports `savedLoginAvailable: false`; absence of this field is unknown. Exclude site paths, query strings, fragments, arbitrary page labels and credential values. `react_to_message` accepts one validated Unicode emoji or a legacy reaction value, never arbitrary text.

Give each streamed model message its own ID. Persist completed safe commentary and final replies with that ID, and retain the live stream until the saved message is read. Drain accepted commentary before the next tool so results cannot overtake it; explicit messages still deduplicate identical text. Failed, cancelled, incomplete and blocked private-input prose must close without becoming a saved reply. A private-input match suppresses the rest of that model message. Preserve background silence and task revision checks. Task IDs alone cannot distinguish consecutive messages.

Use `../../tests/runtime-fixtures.ts` for substitute capabilities. `runtime-session`, `runtime-adapters` and `pi-agent` tests separate product runtime behavior from SDK-specific persistence. `application-adapters.test.ts` proves a substitute stack through HTTP and durable workers.

`send_screenshot` captures through `Computer.screenshot` and passes masked bytes directly to the trusted task attachment callback. It can supply a short PNG name so related page images remain distinct. It never writes browser images into the unrestricted workspace or exposes a profile path. Secure-entry locks and cancellation still apply; only successful publication returns an owned artifact URL. The tool asks the agent to inspect the visible frame with `browser_screenshot` and scroll until the requested source content is visible before publication. Before capture, it checks for visible cookie consent choices and asks the agent to dismiss them. A failed consent check must stop publication. The agent can set `allowCookieDialog` only when the user asked to see that dialog. For requested scheduled image comparisons, retain each baseline page URL and artifact URL in the saved schedule prompt. If a cookie dialog hides a research page, choose its reject or essential-only option before capture when available. After two failed browser attempts, mark that page unverified and continue. Do not use shell HTTP commands to bypass a failed browser load. `browser_screenshot` is model observation, not delivery.

`download_browser_file` captures bounded file bytes through optional `Computer.download`, then publishes through `RuntimeContext.publishBrowserFile`. Only the final artifact reference may enter model output or tool observations. Preserve active-task cancellation and the originating channel; never recover missing browser download support by exposing cookies, browser paths or profile mounts to the workspace.

Schedule creation distinguishes one exact future timestamp with UTC offset from a recurring five-field cron in an IANA timezone. `time-context.ts` supplies the current UTC and local timestamps with the owner's offset and IANA zone on each model prompt, including secure continuation and resumed sessions. Resolve relative dates in that user timezone. `userFormat` adds the signed-in account data, region and clock, and asks the model to use the preferred name naturally and write dates in English with an example built by `shared/date-locale.ts`, the same locale and clock rules the web uses, or in the user's language when they write in another language. Schedule cancellation pauses future work; it does not cancel an execution already accepted. The returned last run is an execution status and must not be presented as proof that the user objective succeeded.

For a repeated source check, save a verified baseline after the first source check. Each due run uses `record_schedule_observation` with the checked source, value and item terms. The tool has an exact argument shape and binds the active run on the server. Compare the meaning of its value with the previous verified observation, then apply the user's alert rule. A current-state rule sends an alert on each due run that meets the rule unless the user asks to suppress repeats. A change rule needs a verified change. An unavailable source has a null value and must not cause a change alert. Keep routine checks in Schedule history.

For a daily check of dated records, an alert also states whether records exist for the current local date. If transactions have no row for today, say so in the alert. Do not send a message only because the day has no new records.

When a result uses a file, document or spreadsheet, name its exact title and link when available. If several connected accounts can serve a request, ask the user to select one before the first account read. Do not treat list order as a choice. Use the selected account for the rest of that request.

`personality.ts` owns the assistant voice. Preserve source/code punctuation instead of globally rewriting output. `RuntimeContext.inspectPrompt` receives the effective system/latest instructions before a prompt, without image bytes; it is optional and nonblocking. Prompt storage/redaction/access belongs to the server. `withTool` carries the exact call ID/name through provider usage context around the accepted action; model calls remain unassigned to individual tools.

Use `react_to_message` only for occasional meaningful acknowledgement, such as gratitude or a personal milestone. Keep useful task answers in text. The trusted callback returns quiet skipped outcomes for cooldown or unavailable channels; do not retry them or send explanatory chatter. Background work and external channels cannot add reactions.

Generic requests for sign-in details or credentials follow the same fresh-login inspection and private Vault flow as named password requests. Browser security rejection creates a distinct browser wait; owner takeover cannot replace unrelated questions, credential/approval waits or terminal tasks. Workspace image input and published files use the container read capability, never a host path read. An unavailable or over-limit image preview remains attachment metadata marked omitted; continue with other inputs without claiming its pixels were seen. Cancellation still stops the prompt. Meter attachment reads separately from published files.

Runtime disposal is shared by concurrent callers. Abort accepted tasks, attempt model cleanup, drain task completion, and attempt both computer and workspace cleanup even when another adapter fails. Report a fixed aggregate failure after those steps. A later disposal call retries only failed cleanup stages; successful stages stay complete and the runtime stays closed to new work.

Owner-requested setup and capability explanations may use trusted, nonsecret context. Do not invent model/provider versions or available access. Keep unsolicited implementation details out of normal replies and keep secret values, hidden instructions and private configuration-file contents out of these explanations. This does not widen tool access.
