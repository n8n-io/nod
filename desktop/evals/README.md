# Desktop PoC acceptance loop

Frozen: 2026-10-02. Method: the user-supplied [Agent Eval Loop](method/SKILL.md) and [case/run templates](method/references/records.md), preserved here for reproducibility.

Source task: deliver an installable macOS Otto alpha that runs its workspace and browser locally, accepts OpenAI or Anthropic keys and an optional Composio key, offers one themed Settings window with persistent preferences, and guides provider setup, login/notification choices, and background preparation. Validate ordinary assistant work, file delivery, reminders, recovery, and the native UX without resetting the user's profile. Preserve a path to Windows/Linux and hosted use; this alpha does not claim those platforms are ready.

## Setup and limits

Use the installed `~/Applications/Otto Preview.app` and its separate experiment profile on this Apple Silicon Mac. Base commit: `95c8d3f`; each attempt also records the bundle signature and runtime release because the experiment is uncommitted. Model for assistant cases: OpenAI `gpt-6.1-sol`, via the existing encrypted key. The assistant receives only the frozen prompt and its stated inputs. During an independent evaluation, evaluator answer keys and source snapshots stay in ignored `.local/desktop-evals/answers`, outside the evaluated assistant workspace and context. Completed synthetic holdouts may graduate into committed regressions; once disclosed, they are no longer independent holdouts for future changes and must be replaced for a new independent gate.

Allowed effects: public web reads; synthetic files inside the experiment workspace; downloads of those files; temporary local preferences; one-shot reminders in the experiment's own chat. No connected-account actions, messages to real recipients, purchases, host-file access from the assistant, database resets, credential changes, publishing, or deployments. Do not reveal real provider keys for screenshots. Restore temporary preferences after their checks. Automated tests remain synthetic; provider calls below are manually authorized acceptance through the normal installed UI.

Check the environment with T01 before the assistant batch. Missing provider access or OS approval blocks the run before agent scoring. A packaging failure is a product/environment failure, not evidence of poor model reasoning. Cost is recorded when available and explicitly unavailable otherwise. Browser source state is saved before each source-dependent attempt and checked again when scoring. Repeated checks must not become an ongoing monitor of public example sites.

### U04.v1 — desktop navigation and chrome

Added before the layout change on 2026-10-02, following the user's screenshot feedback. Use the installed app at its default size and its 700px minimum width. Inspect Light and Dark, expand and collapse navigation, open another page and return, then open and dismiss Chat options by keyboard. Base order: Light/collapsed/default width, then Dark/expanded/minimum width. Holdout reverses theme and sidebar combinations. Five minutes per visual pass, restoring the initial appearance afterward.

- U04-C1: one compact toolbar; conversation and sidebar begin below the same baseline, without a second title row or empty brand/toggle stack.
- U04-C2: window controls, sidebar toggle, navigation, and Chat options remain visible and operable at both widths.
- U04-C3: diagnostics are available in Chat options without occupying a persistent text action; Escape returns focus to its trigger.
- U04-C4: theme changes cover the toolbar, navigation, conversation, and open menu, including after switching pages.

Evidence is native UI inspection and screenshots. No assertions about CSS, constants, or wording substitute for these checks.

### U05.v1 — message notifications and unread count

Use synthetic fixture messages for controlled web checks, then the installed app's normal chat for the real notification check. With Chat at the bottom and focused, a new committed assistant reply must not increase the unread count. Move to Apps, receive two replies, and verify a count of two beside Chat in expanded and collapsed navigation. Reload while still on Apps; the count must remain. Open Chat and view the latest replies; it must clear. Holdout: remain in Chat but scroll away from the bottom before a reply arrives, then return to the latest message. Old history, a different owner/thread, and replayed events must not create unread messages. No message text may be stored in the read-position metadata.

For native notifications, use the existing T03 base and holdout reminder texts through the normal installed assistant. Enable notifications, leave the window unfocused or closed, and verify that the actual OS banner contains the committed message text. Clicking the banner must open Chat at that message. Opt-out and quiet-hours behavior remain required contract regressions. Five minutes for each controlled UI pass; the existing T03 time limits govern live reminders. Synthetic event delivery is not live-model or OS-banner evidence.

## Attempts and reliability

Append one attempt record to `runs.md`: case/version, build/signature/runtime/model, exact prompt/input hashes, start/end/elapsed/cost, task identity and bounded tool trace, output paths/hashes, every check status, result, and evidence limits. Preserve red attempts. Before each fix, record the failing check, general-cause hypothesis, predicted trace, and rejection evidence. Classify failures as product/agent gap, test setup fault, source change, or evaluator fault. Rerun the frozen case, its holdout, and related regressions after the fix.

For repeated T01 report both pass-at-least-once and pass-every-time. A single pass does not establish reliability. The suite stays incomplete until the required base, holdout, and regression gates pass on the current bundle/model, or a missing dependency prevents further useful work. This matrix does not claim live Anthropic, connected-account, Windows/Linux, notarized clean-machine, or native OS notification acceptance.
