# Desktop automatic updates

Frozen: 2026-10-04, before implementation. Method: [Agent Eval Loop](method/SKILL.md). Source task: provide seamless desktop updates through n8n while the repository is private, prompt before restarting, preserve work, and allow a later switch to GitHub.

One case passes only when all of its applicable checks pass in the same attempt. A missing signing or operating-system environment blocks the native case before scoring. Preserve failed attempts and record the tested commit, fixture hashes, start/end times, actual observations, and cleanup. No model, connected user account, real recipient, normal Otto profile, or production signing credential is used by these cases.

| Case             | User task and controlled setup                                                                                                                                                                                                                    | Required outcome                                                                                                                                                                        | Limit                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| UPD-NATIVE.v1    | “Install the available update and reopen with my saved information.” Two small signed Electron applications, versions 1.0.0 and 1.0.1, a unique fixture bundle identifier, synthetic profile, local HTTP feed, and temporary CI signing identity. | The native updater downloads the exact ZIP, replaces the old application, reopens version 1.0.1, and retains the synthetic profile value.                                               | One attempt; five minutes after launch; macOS CI only.                  |
| UPD-SIGNATURE.v1 | “Install the available update.” The same fixture, but the offered application has a different signing identity.                                                                                                                                   | The actual native updater rejects it after reaching the ZIP; the installed application remains version 1.0.0 and the profile stays intact.                                              | One attempt; two minutes after launch; macOS CI only.                   |
| UPD-RESTART.v1   | “Restart to install the update.” Existing desktop controller with synthetic work, draft, attachment, and failed-drain states.                                                                                                                     | No restart while any state is unsafe. An acquired drain is released after failure, and a later authorized idle restart closes the existing lifecycle before handing off installation.   | Deterministic contract cases, no Electron installation or live service. |
| UPD-RUNTIME.v1   | “Prepare this update.” A candidate with a content-addressed runtime descriptor and disposable cache. Holdouts change the runtime identity, files, archive bytes, or current-runtime claim.                                                        | Only the matching verified runtime reaches readiness before application staging. Failure preserves the running runtime and existing profile.                                            | Deterministic filesystem and local-download cases.                      |
| UPD-DELIVERY.v1  | “Find the next update for this app.” Synthetic published, draft, obsolete, unrelated, malformed, and incomplete GitHub release records.                                                                                                           | Only a newer complete desktop release is selected. Exact release/asset membership and fixed repository bounds survive redirects; runtime and application remain bound to one candidate. | Deterministic adapter/workflow cases; no GitHub credential.             |

## Native checks

| ID           | Applicability     | Observable pass condition                                                                                                                    | Evidence and method                                              |
| ------------ | ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- |
| UPD-SCOPE    | Both native cases | Every application, profile, certificate and cleanup path belongs to the unique fixture; production profile and trust settings are untouched. | Owned paths, bundle IDs and cleanup receipt; code.               |
| UPD-BASE     | Both native cases | Version 1.0.0 launches and reads the independently supplied synthetic profile value.                                                         | Application event receipt and profile hash; code.                |
| UPD-DOWNLOAD | Both native cases | The native updater requests the feed and exact ZIP and receives the frozen archive bytes.                                                    | Local server receipt, archive SHA-256 and byte count; code.      |
| UPD-INSTALL  | UPD-NATIVE        | Native replacement installs and launches version 1.0.1 at the same application path.                                                         | Relaunched application receipt and signed bundle metadata; code. |
| UPD-REJECT   | UPD-SIGNATURE     | A signature error follows the ZIP request, without an update-downloaded event or application replacement.                                    | Native error receipt and unchanged signed bundle; code.          |
| UPD-DATA     | Both native cases | The saved synthetic profile bytes remain unchanged.                                                                                          | Before/after SHA-256 and relaunched application receipt; code.   |
| UPD-CLEANUP  | Both native cases | Owned application processes stop, local server closes, and the temporary keychain and fixture files are removed.                             | Cleanup receipt; code.                                           |

The native fixtures establish Electron/Squirrel signing, installation and relaunch behavior with the pinned framework. They do not prove the full Otto UI, live n8n/PAT access, model/account behavior, notarized distribution, or a fresh user’s Gatekeeper experience. The restart/runtime/delivery contract cases cover the production orchestration separately. A real update from one released Otto version to the next remains a distinct receiving-user acceptance check; version 0.1.0 has no updater and requires a manual first upgrade.

## Native result

The first [macOS acceptance run](https://github.com/n8n-io/otto/actions/runs/37220336375) passed both frozen cases on 2026-10-04. Tested PR merge commit: `3ce8a8ca15de161151779416160329be64b7cd3d`, containing updater head `8d22e3ab922b1d8acb1add7386b1b0cd0794095b`. Fixture SHA-256: `79ef4d2f3d2a3c7f9333d4936418114a35d111fa1fd63f84c5a0069f30e65268`.

The correctly signed ZIP was requested, installed and relaunched as 1.0.1 at the original application path with identical saved profile bytes. The different-signer ZIP was requested and rejected by the native signature requirement; version 1.0.0 and its saved profile remained intact. Scope and cleanup checks passed in the same attempt. The run used Electron 44.5.0 on a disposable macOS runner and took 167 seconds including fixture packaging. The downloaded JSON receipt is retained under ignored `.local/desktop-update-validation/native-8d22e3a/` and in that run's `native-update-acceptance` artifact.
